# 6. Memory Management and Virtual Memory

## 1. Why Memory Management? ⭐⭐⭐

The OS must allocate RAM, keep processes isolated, and make execution efficient.

```text
Process sees logical/virtual addresses
                  ↓ translation
Hardware + OS use physical RAM addresses
```

## 2. Logical vs Physical Address

```text
Logical (virtual) address → generated by CPU; visible to process
Physical address          → actual location in RAM
```

The **MMU (Memory Management Unit)** performs translation. This lets each process behave as if it has its own private address space.

## 3. Address Binding

```text
Compile time → address fixed before execution
Load time    → address chosen when program is loaded
Run time     → address translated while running; supports relocation/VM
```

Modern general-purpose OSs rely heavily on run-time binding.

## 4. Contiguous Allocation and Fragmentation

In contiguous allocation, each process gets one continuous physical block.

```text
| OS | P1 | free | P2 | free | P3 |
```

```text
Internal fragmentation → wasted space inside allocated block
External fragmentation → free memory exists but is split into small holes
```

**Compaction** can combine external holes, but moving memory is expensive and requires relocation support.

### Fixed vs Variable Partitions and Fit Strategies

```text
Fixed partitions    → predefined block sizes; simple, internal fragmentation
Variable partitions → allocate requested-sized region; external fragmentation
```

When variable-size holes exist:

```text
First fit → first hole large enough; fast and common
Best fit  → smallest adequate hole; can leave many tiny holes
Worst fit → largest hole; leaves a large remainder, often not best in practice
```

**How to solve:** scan the free-hole list in the order stated, apply the selected rule, then reduce that hole by the allocated size.

## 5. Paging ⭐⭐⭐

Paging splits virtual memory into fixed-size **pages** and physical memory into equal-size **frames**.

```text
Virtual address = page number | offset
                    ↓
               page table
                    ↓
Physical address = frame number | offset
```

A process's pages can occupy non-contiguous frames.

```text
Page 0 → Frame 5
Page 1 → Frame 2
Page 2 → Frame 9
```

Benefits: no external fragmentation; easy allocation/protection.  
Cost: page-table memory and translation overhead; possible internal fragmentation in final page.

## 6. Page Table and TLB ⭐⭐⭐

A **page table** maps virtual page numbers to physical frame numbers and permissions.

```text
Page-table entry may include:
frame number | valid bit | read/write/execute | dirty bit | reference bit
```

A **TLB (Translation Lookaside Buffer)** is a small, fast cache of recent page-table translations.

```text
Virtual address
   ↓
TLB hit  → fast translation
TLB miss → page-table lookup, then update TLB
```

> **TLB miss ≠ page fault.** A TLB miss may be resolved from a page table in RAM; a page fault means the page is not currently in RAM.

## 7. Multilevel Paging and Segmentation

Very large address spaces make one giant page table wasteful. **Multilevel paging** allocates lower-level tables only where needed.

**Segmentation** divides memory into logical variable-size parts such as code, stack, and data.

```text
Paging      → fixed-size blocks; physical allocation friendly
Segmentation→ logical variable-size units; programmer-view friendly
```

Modern systems commonly use paging, sometimes with segmentation concepts or limited hardware support.

| Paging | Segmentation |
|---|---|
| Fixed-size pages | Variable-size logical segments |
| Avoids external fragmentation | Can suffer external fragmentation |
| Transparent to most programs | Mirrors logical units such as code/data |

## 8. Virtual Memory and Demand Paging ⭐⭐⭐

**Virtual memory** lets a process use an address space larger than physical RAM by keeping inactive pages on disk and loading pages on demand.

```text
CPU references page
    ↓
Page in RAM? ─ yes → continue
    │ no
    ↓
Page fault → OS loads page from disk → restart instruction
```

A page fault is normal in demand paging, but is much slower than RAM access.

### What the OS Does on a Page Fault

```text
Reference absent page
  ↓
Trap to OS; check that reference is valid
  ↓
Find free frame or select a victim (write victim if dirty)
  ↓
Read needed page into frame; update page table/TLB
  ↓
Restart the faulting instruction
```

## 9. Page Replacement ⭐⭐⭐

If RAM has no free frame, OS chooses a victim page.

| Algorithm | Core idea | Important point |
|---|---|---|
| FIFO | replace oldest loaded page | can show Belady's anomaly |
| Optimal | replace page used farthest in future | theoretical benchmark; future unknown |
| LRU | replace least recently used page | approximates locality; exact implementation costly |
| Clock / second chance | FIFO-like with reference bit | practical LRU approximation |

**Belady's anomaly:** with FIFO, increasing frames can sometimes increase page faults. It does not occur in stack algorithms such as optimal/LRU.

**How to solve a replacement question:** write the reference string one item at a time, show the current frames after every reference, and mark a fault whenever the referenced page is absent. For optimal, look forward; for LRU, look backward; for FIFO, evict the earliest-loaded page.

## 10. Thrashing and Working Set

**Thrashing** occurs when the system spends most time handling page faults rather than useful work.

```text
Too many active processes
   ↓
Too few frames each
   ↓
Frequent faults / disk I-O
   ↓
Low CPU useful work
```

The **working set** is the pages a process actively needs during a recent interval. Giving processes enough frames for their working sets helps avoid thrashing.

## 11. Copy-on-Write (COW)

Initially share a memory page; copy it only when one party writes.

```text
Parent and child share pages
        ↓ write to page
OS creates private copy for writer
```

This makes process creation efficient when the child soon executes another program.

## 🧠 One-Minute Revision

```text
Virtual address → MMU/page table → physical address
Page = virtual fixed-size block
Frame = physical fixed-size block
TLB = translation cache
TLB miss ≠ page fault
Demand paging → load page only when referenced
Thrashing → excessive page faults, little useful work
```
